# Summary

Data visualization packages like CanvasXpress provide rich features for exploring datasets but have high learning curves requiring web development skills. We demonstrate how guided autocomplete and Large Language Models (LLMs) can be used together to simplify visualization creation. Users upload datasets and describe desired visualizations in plain English, guided by autocomplete suggestions or free-form text. Following guided suggestions generates configurations with perfect accuracy, while LLMs serve as backup with high accuracy. The guided autocomplete system generates synthetic training data at scale for few-shot prompting or LLM fine-tuning. We evaluate accuracy using thousands of synthetic examples with Retrieval Augmented Generation (RAG), achieving over 97% exact match accuracy. Results show accuracy increases with more few-shot examples but decreases with prompt complexity (4 vs 6 vs 10 sentences), demonstrating that complex visualization requests are more challenging for LLMs.

# Statement of Need

CanvasXpress [@neuhaus_canvasxpress_nodate] is a JavaScript library for creating interactive data visualizations using HTML5 canvas technology. It supports various chart types with extensive customization through JSON configuration objects. However, the requirement for coding skills creates barriers for domain scientists in genomics, proteomics, and clinical studies who have deep field knowledge but limited programming skills. This creates a research challenge: can we enable visualization creation through natural language descriptions?

We created a system leveraging guided autocomplete and LLMs for conversational visualization generation. CanvasXpress is particularly suitable for LLM-based generation due to: (1) well-structured JSON schema with semantically meaningful field names; (2) declarative approach compatible with one-shot LLM generation; (3) sensible defaults and graceful handling of missing parameters; (4) scientific domain focus matching researcher needs. Unlike procedural libraries requiring complex code generation, CanvasXpress's declarative configurations provide natural targets for LLM generation.

# Implementation

## Guided Autocomplete

Guided autocomplete helps users build prompts incrementally by suggesting valid completions. Users typing "Create" see options like "a bar graph" or "a line chart." This ensures perfect accuracy when followed completely, with LLMs serving as backup for free-form input. The system, called "CoPilot," draws from menu-based natural language approaches [@tennant_menu-based_1984] and generates synthetic prompt/config pairs for LLM training.

## Prompt Engineering and RAG

We use few-shot prompting [@brown_language_2020; @schulhoff_showing_2024] with examples automatically generated by the guided autocomplete system—not manually curated. This automated approach generates thousands of diverse, high-quality examples efficiently. We provide schema information for ~150 most-used CanvasXpress fields (of ~1500 total) due to context window limits.

Retrieval Augmented Generation (RAG) [@gao_retrieval-augmented_2023] uses vector databases for efficient few-shot example selection. We create 1024-dimension semantic vectors using BGE-M3 embeddings [@chen_bge_2024] stored in PyMilvus/Milvus [@wang_milvus_2021; @guo_manu_2022]. User queries are vectorized and matched against the 25 most semantically similar examples.

# Accuracy Assessment

We evaluated two factors: number of few-shot examples (100-2500 in increments of 100) and prompt complexity (maximum 4, 6, or 10 sentences). For each synthetic prompt, we generated three alternative phrasings using GPT-4o. Accuracy metrics include exact match percentage and JSON similarity score using recursive comparison of structure and values.

Few-shot examples were systematically generated covering: (1) common chart types; (2) different data structures; (3) customization options. We generated up to 2,500 examples for evaluation across complexity levels.

Key findings: Accuracy improves with more few-shot examples then plateaus, with the 4-sentence dataset showing slight decrease around 1800 examples. Accuracy is excellent (>97%) for all datasets but decreases with complexity—4-sentence prompts outperform 6-sentence, which outperform 10-sentence prompts. This suggests longer, more complex descriptions pose greater challenges for LLMs.

Future work includes fine-tuning LLMs using synthetic data (thousands of examples easily generated by the copilot) and developing agentic systems using AWS Bedrock for multi-step analysis workflows and autonomous data exploration.

# Research Impact

Our system addresses research challenges by: (1) reducing time from analysis to visualization; (2) enabling exploration of more visualization options without technical barriers; (3) eliminating need for specialized programming support; (4) accelerating research in data-intensive domains. For example, genomics researchers can generate complex heatmaps by describing "show me a heatmap of gene expression levels across tissue types, clustered by similarity" rather than learning JSON syntax.

# Related Work

While RAG and few-shot learning are established techniques, their application to scientific visualization generation is novel. Standard RAG focuses on text generation, whereas we generate structured JSON configurations. Our approach uses guided autocomplete for automatic synthetic example generation, avoiding manual curation typical in few-shot applications.

Most visualization libraries present challenges for LLM generation: D3.js requires DOM manipulation, ggplot2 uses sequential function calls, Matplotlib relies on procedural commands. These require syntactically correct executable code rather than declarative configurations. CanvasXpress's JSON-based approach creates natural LLM targets with graceful parameter handling and meaningful defaults.

# User Interface

We integrated the CoPilot and LLM generation UI into every CanvasXpress visualization, making it the first standalone JavaScript library leveraging client-side AI. JSONP calls ensure fast access to canvasxpress.org servers, sending only prompts, parameters, and headers to minimize load. Users can also implement their own services. The integrated UI allows describing new visualizations through guided copilot or free-form text, with results replacing current visualizations or adding new ones.

The system is implemented as a professional Python package with modular architecture, featuring comprehensive automated testing with over 85 unit and integration tests validating both real API functionality and graceful fallback to mock responses when external services are unavailable.
